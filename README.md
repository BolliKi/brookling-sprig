# Brookling · 灵宠禾禾（Sprig）

宋韵山水水榭中的互动灵宠：四种情绪、十二种动作变体、2D / 3D 双形态、童声预生成语音与 TTS 回退、可收起的对话手记与右侧调试台。

> **在线预览**：暂未部署。本地按下方命令启动后访问 <http://localhost:3000>。

## 快速开始

### 环境要求

- Node.js **≥ 18.17**（建议 20 LTS 或更高）
- pnpm（仓库已声明 `packageManager: pnpm@11.25.0`；也可使用 npm，见文末）

### 安装并启动

```bash
pnpm install
pnpm dev
```

打开 <http://localhost:3000>。

- 默认进入 **立体视图**，默认 **开启声音**；点击标题栏的声音按钮可关闭童声与古琴泛音（固定台词优先播放预生成音频）。
- 调试台：<http://localhost:3000/?debug=1>，或在标题栏点击「调试」。

### 生产构建

```bash
pnpm build
pnpm start
```

### 其他命令

```bash
pnpm typecheck
```

```bash
pnpm lint
```

```bash
pnpm dev:preview
```

`dev:preview` 使用独立构建目录 `.next-preview`，固定运行在 <http://localhost:3013>，可与 3000 端口的开发实例并存，用于走查和截图验证。

```bash
pnpm dev:verify
```

`dev:verify` 使用 `.next-verify` 构建目录，固定运行在 <http://localhost:3014>，用于与预览实例并行的独立验证。

### 生成预置语音

```bash
pnpm voice:generate
```

读取情绪台词、意图回复、风铎与初始问候，调用 Edge TTS 生成固定台词音频到 `public/voice/`，并写入 `src/configs/voice-manifest.json`。默认只生成 `CRISP_GIRL`；`--preset=all` 生成三套童声，`--force` 强制重录，`--dry-run` 只统计台词。

需要 Node 22.6+ 与 `uv`/`uvx`（macOS 可 `brew install uv`）。首次生成视网络约 5–15 分钟；已生成的音频会跳过。音频与清单需要一起提交，静态构建才能直接播放。修改固定台词后重新运行脚本；未命中的新台词会自动回退到浏览器 TTS。

`voice-preview/` 是本地音色试听页，不参与构建；可运行 `python3 -m http.server 3021 --directory voice-preview` 后访问 <http://localhost:3021>。

### 使用 npm

```bash
npm install
npm run dev
```

其他脚本同理替换为 `npm run <script>`。

## 部署到 Cloudflare Pages

项目为纯前端静态站点，可直接托管在 Cloudflare Pages：

1. Cloudflare 控制台 → **Workers 和 Pages** → **创建** → **Pages** → **连接到 Git**，选择 `BolliKi/brookling-sprig` 仓库。
2. 构建设置按下表填写：

   | 字段 | 值 |
   | --- | --- |
   | 框架预设 | `无`（None） |
   | 构建命令 | `NEXT_OUTPUT=export npm run build` |
   | 构建输出目录 | `out` |
   | 根目录 | 留空 |

   环境变量（可选）：`NODE_VERSION` = `20`。

3. 保存并部署，完成后访问 `https://<项目名>.pages.dev`。

`NEXT_OUTPUT=export` 会让 `next.config.mjs` 切换为静态导出、产物写入 `out/`；本地 `pnpm dev` / `pnpm start` 不受影响。

## 功能与默认体验

- 面向用户时默认进入 **立体视图**，主画面只保留心情、当前动作、平面 / 立体切换、声音、对话与快捷互动，不出现调试参数。
- **立体视图拥有真正的 3D 背景**：远景宋韵画卷（天穹、崇山、日月、云气）沿用原有 Canvas 绘制并烘焙为贴图；近景水面、青石台基、水榭廊柱、墨竹、青莲、乌篷舟与飞雁由 three.js 几何体搭建。左右拖动灵宠时镜头轻环绕，远山几乎不动、近景明显位移，形成真实视差。WebGL 或 CDN 不可用时自动回落到平面画卷。
- **默认开启声音**：童声与古琴泛音随交互直接播放，点击标题栏的声音按钮可随时静音；固定台词播放预生成音频，动态兜底回复回退浏览器 TTS。受浏览器自动播放策略限制，首次发声需发生在用户点击之后。
- **动作有完整演出**：每段动作 4–5 秒后自动结束，并随机切换到一个待机动作；调试台可锁定状态以便观察。
- 对话以左下角浮动手记卡呈现，历史保留最近 40 条并可滚动回看；点击互动只追加禾禾的话语，只有输入框发言才显示用户气泡。
- 立体视图有独立的出场序幕：米浆画卷、竖式道教符箓（敕 / 太上老君 / 急急如律令）、环绕符文与进度仪式，字符逐笔显形并绕行；引擎就绪后画卷向两侧展开。加载层固定在页面根节点，全屏显示，不再被舞台变换裁成中央方块。
- 左侧对话展开时，灵宠居中于右侧可用区域；对话收起后回到屏幕正中。桌面端两种站位切换时，灵宠会播放侧步行走（3D 转身迈步 / 2D 摆腿摆爪），不是生硬平移。
- 对话卡可收起为左下角小签（500ms 滑动淡出/淡入）；收起后，较早的宠物台词以弹幕形式飘过画面，最新一句会以角色身旁的随身气泡出现，约 5 秒后自动淡出，新台词会重新弹出。
- 维度转场分两套：3D → 2D 为「归卷」（红枫散躯 + 画卷合拢再展开），2D → 3D 为「破卷」（纸片崩解 + 金色冲击环与光柱）；两向效果与图层动画均不同。
- 连续点击有 850ms 节流；拖拽旋转立体视角不会误触发点击动作。
- **背景画卷由本地时间决定**（清晨 / 白昼 / 暮色 / 夜色），不随心情切换时段。
- **心情只驱动氛围层**：光影颜色与强度、漂浮微光的数量与速度、粒子形态都会随情绪平滑过渡。
- 状态监控与远程调试台改为 **右侧抽屉**：点击标题栏「调试」，或访问 `/?debug=1` 打开。面板内提供实时情绪状态码与互动日志，并可强制切换动作状态、覆盖背景灯光主题、向主画面发送系统提示气泡。
- 系统通知在画面上方居中堆叠显示，可同时展示多条；悬浮时暂停淡出并轻微上浮。

## 技术栈

- Next.js 14 · App Router
- React 18 · TypeScript
- TailwindCSS 3（设计令牌位于 `@core/tailwind/theme.ts`）
- lucide-react 图标
- three.js r128（运行时由 CDN 动态加载，保持原型的 3D 灵宠行为；立体背景复用同一份运行时）
- 立体背景 = 远景 CanvasTexture 画卷 + 近景程序化几何体（水面、石台、廊柱、墨竹、飞雁）

## 分层约定

- **app**：只处理路由、布局与全局样式。
- **views**：页面级装配；从会话控制器取数据，分发给各功能组件。
- **components**：按功能域拆分的展示组件，不直接持有跨域状态。
- **hooks**：行为逻辑；`useCompanionSession` 是唯一的会话编排入口。
- **configs**：纯数据表（情绪、晨昏主题、心情氛围、语音、文案、按钮）。
- **libs**：与 React 无关的领域服务（语义识别、晨昏判定、音频合成、音源排序）。
- **背景与心情分离**：`libs/scene/time-of-day.ts` 决定背景晨昏；`configs/mood-atmospheres.ts` 决定心情光影、漂浮物与微动效节奏。
- **@core**：与灵宠业务无关的公共能力（设计令牌、通用组件、动画、颜色工具）。

## 开发复盘（交付物 3）

### ① 使用的 AI 工具与实际耗时

| 项目 | 说明 |

| 辅助能力 | 浏览器 Preview / Playwright 做截图、控制台与布局检查；本地 `tsc --noEmit`、ESLint 与生产构建做回归 |
| 实际耗时 | **约 2–3 小时**：前 10 多分钟生成页面主题、交互与模型雏形，后续主要做风格收敛、细节优化与浏览器走查 |
| 人工介入 | 集中在 UI 风格收敛、文案密度、动效手感与状态时长 |

使用方式：先把原型迁到 Next.js 分层结构，再按「一屏一屏看、一处一处改」做浏览器走查；关键轮次后跑 `tsc --noEmit`、ESLint 和生产构建，避免只凭截图判断。

### ② AI 最初没写好、被我手动要求改掉的细节

**主案例：页面 UI 的「AI 味」与风格漂移**

- **AI 最初的做法**：框中框、爱用表情、描述重复、花里胡哨的节目式设计，以及密密麻麻的文字；每个组件都想说话，页面没有统一的视觉规则。
- **我的判断**：问题不在某一个组件，而在缺少「什么该出现、出现在哪里」的边界。必须先确定风格，再限制文案的层级与输出位置。
- **我的要求**：以宋韵山水为唯一视觉母题；主画面只保留状态与对话，说明性文案收进对话卡或调试台；去掉表情和多余的面板嵌套；动效只服务状态变化，不做无目的的演出。
- **改后**：
  - 统一设色、字体、圆角与描边：米纸底、墨褐字、朱砂 / 赭石点缀，标题宋体、正文楷体。
  - 主画面收敛为「舞台 + 顶部状态栏 + 一张手记卡」；对话、快捷操作与输入合并到同一张卡，不再为每个功能各开一块面板。
  - 清掉表情符号，只保留功能性图标；文案只留「心情 / 当前动作 / 视图 / 声音」与对话，系统通知独立居中堆叠，状态码、日志、灯光覆盖等说明全部收进右侧调试抽屉。
  - 动效只服务状态：归卷 / 破卷、弹幕、氛围层各有叙事目的，不做无意义的循环演出。
  - 结果：页面从「每个组件都在说话」变成「一个世界 + 一处对话」。

**另一个细节：3D ↔ 2D 转场「两个方向共用一套动画」**

- **AI 最初的做法**：两个方向共用同一套红枫化形遮罩，切换观感几乎一样，缺少方向差异与记忆点。
- **我的判断**：这是产品里最强的「形态切换」时刻，不能只做参数级差异，方向本身应该有叙事。
- **我的要求**：两个方向必须不同，而且要比当前版本更有记忆点。
- **改后**：拆成 3D → 2D「归卷」与 2D → 3D「破卷」两套 1.5s 动画，由 `DimensionalMorphOverlay.tsx` 按 `toMode` 分流：前者是红枫散躯 + 画卷合拢再展开，后者是纸片崩解 + 金色冲击环与光柱。

**共同点**：AI 的默认美学倾向是「加」——加卡片、加表情、加解释、加特效；我的修正都是先划边界（什么不出现、出现在哪里），再让剩下的元素服务同一个主题。

## 说明与已知限制

- 对话由本地关键词意图识别 + 情绪台词库驱动，**不调用后端或大模型 API**；刷新页面会重置会话。
- 固定台词优先播放 `public/voice/` 下的预生成音频；只有包含用户原话的动态兜底回复才会回退到浏览器 TTS。音频加载或播放失败时同样自动回退。
- 预生成音频由 Edge TTS 生成，默认音色为 `CRISP_GIRL`（XiaoyiNeural 升调）。Edge TTS 是社区封装接口，商用请确认条款，或改用 Azure / 其它云 TTS 重新生成。
- 实时兜底使用浏览器 Web Speech API，中文音色取决于系统 / 浏览器；建议使用 Chrome 或 Edge。
- three.js r128 通过 CDN 动态加载；离线或 CDN 被阻断时，3D 灵宠会显示加载提示，立体背景自动回落到平面画卷，2D 视图不受影响。若需离线部署，可改为 npm 依赖并按需动态导入。
- 预生成音频与清单（`public/voice/`、`src/configs/voice-manifest.json`）属于构建产物，需随仓库一起提交；删除后运行 `pnpm voice:generate` 可重新生成。
- 立体背景的远景贴图在主题切换时以 900ms 交叉淡化；近景材质同步做颜色插值，与平面画卷的晨昏过渡节奏一致。
- 原型源文件未随仓库提交；`tsconfig.json` 中仍保留其排除项，便于后续放回对照。
